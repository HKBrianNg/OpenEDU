为什么选 ESLint？

虽然当前界面默认选中的是 Oxlint，但对于你现在的项目阶段，ESLint​ 是更稳妥的选择：

生态成熟与教程丰富：ESLint 是前端领域多年的标准，几乎所有的 React + TypeScript 教程、脚手架和开源项目都是基于 ESLint 配置的。遇到问题时，你能轻松找到解决方案。
插件支持完善：后续我们计划引入 Ant Design (antd)、路由等，ESLint 有极其丰富的插件生态（比如专门检查 React Hooks 的插件），而 Oxlint 作为较新的工具，在某些特定框架规则的支持上还不如 ESLint 全面。
避免踩坑：Oxlint 虽然速度极快（比 ESLint 快几十倍），但目前仍处于发展阶段，有时可能与某些复杂的 TypeScript 配置或旧版插件存在兼容性问题，初期学习阶段没必要给自己增加额外的排查成本。

## 4. 关键优势

1. **所有 JSON 全部托管 CDN**：课程主文件、章节课时 json 都放在 `img-library` 仓库，前端无本地 mock 文件，打包体积更小；
2. **自动路径转换逻辑不变**：
   - `/audio/xxx.mp3` / `/lyric/xxx.lrc` / `/images/xxx.jpg` → 自动拼接完整 CDN 链接；
   - `https://` 外链视频、`/articles` 路由文本保持原样不处理；
3. **数据更新无需重打包前端**：只需要在 GitHub 仓库更新 JSON、音频、图片，CDN 自动生效；
4. 统一入口管理，新增课程仅需在仓库新建 `course-x` 文件夹，前端调用 `fetchFullCourse("course-x")` 即可加载；
5. 全环境共用一套 CDN 地址，无本地开发静态资源分支。

/////////////////////////////////////////
getHardMove 决策流程（开发框交付版）
输入
board: 当前棋盘

side: AI 执棋方（RED / BLUE）

moves: AI 当前所有合法走法列表

timeLimit: 思考时间上限（毫秒）

输出
Move: 最佳走法，或 RESIGN_MOVE（认输）
////////////////////////////////////////
流程
第一阶段：本能层（任何时候都执行）

1. 遍历 moves，检查是否存在一步必胜走法（走完后对手兽穴被占）
   → 有则直接返回该走法

2. 遍历对手所有走法，检查是否存在一步必胜走法（走完后 AI 兽穴被占）
   → 有则检查 AI 能否阻止（吃掉威胁棋子 / 走到兽穴前阻挡）
   → 无法阻止则返回 RESIGN_MOVE
////////////////////////////////////////
第二阶段：预判层（选择预判深度）

1. 统计棋盘上双方剩余棋子总数 pieceCount
2. 根据 pieceCount 选择预判步数 lookAheadSteps：
   - pieceCount ≤ 4（残局） → lookAheadSteps = 10
   - pieceCount ≤ 8（中局） → lookAheadSteps = 5
   - 否则（开局/复杂局面） → lookAheadSteps = 3

3. 调用 lookAhead(board, side, lookAheadSteps)，返回评估结果：
   {
     aiCanWinIn: number | null,  // AI 最快几步能赢，null 表示无法在 lookAheadSteps 内赢
     oppCanWinIn: number | null, // 对手最快几步能赢，null 表示无法在 lookAheadSteps 内赢
   }

///////////////////////////
第三阶段：策略层（基于预判结果）
if (oppCanWinIn !== null && oppCanWinIn <= lookAheadSteps && (aiCanWinIn === null || aiCanWinIn > oppCanWinIn)):
  → 对手能在预判步数内赢，且 AI 无法更快取胜
  → 检查 AI 是否有走法能延迟对手取胜
  → 有则选择最佳防守走法
  → 无则返回 RESIGN_MOVE

else if (aiCanWinIn !== null && aiCanWinIn <= lookAheadSteps):
  → AI 能在预判步数内赢，且对手无法更快取胜
  → 使用进攻搜索（深度 = aiCanWinIn + 2）

else if (aiCanWinIn !== null && oppCanWinIn !== null):
  → 双方都有机会
  → 使用标准 Alpha-Beta 搜索（深度 = lookAheadSteps）

else:
  → 均势或局面不明朗
  → 使用标准 Alpha-Beta 搜索（深度 = lookAheadSteps - 1）

////////////////////////////////////
对搜索返回的最佳走法，执行 2 层快速验证：
- 如果验证分数低于必败阈值 → 返回 RESIGN_MOVE
- 否则返回最佳走法

//////////////////////////////////
关键函数说明

函数                                作用
lookAhead(board, side, steps)       评估未来 N 步内双方的取胜可能性，返回最快取胜步数
attackSearch(board, side, depth)    激进 Alpha-Beta 搜索，鼓励进攻
standardAB(board, side, depth)      标准 Alpha-Beta 搜索，均衡攻守
findBestDefense(board, side)        寻找最佳防守走法
evaluateBoard(board, side)          局面评估函数，返回分数
RESIGN_MOVE                         认输标志，{ from: { row: -1, col: -1 }, to: { row: -1, col: -1 } }

////////////////////
测试要点（供测试框参考）
本能层测试
构造 AI 一步必胜的局面 → 应直接返回胜着，不走搜索
构造对手一步必胜且 AI 无法阻止的局面 → 应返回 RESIGN_MOVE
构造对手一步必胜但 AI 能吃掉威胁棋子的局面 → 应返回吃子走法
预判层测试
残局（双方共 ≤4 子）→ 预判深度应为 10
中局（双方共 5-8 子）→ 预判深度应为 5
开局（双方共 >8 子）→ 预判深度应为 3
策略层测试
AI 能在 3 步内赢且对手无法阻止 → 应选择进攻走法
对手能在 3 步内赢且 AI 无法阻止 → 应返回 RESIGN_MOVE
双方都有机会 → 应进入标准搜索
边界测试
棋盘无合法走法 → 返回 null
时间耗尽 → 返回当前最佳走法，不崩溃
RESIGN_MOVE 的坐标应为 (-1, -1)
